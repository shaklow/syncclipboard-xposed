# SyncClipboard Xposed

[**简体中文**](README.md) | **English**

An LSposed/Xposed module that syncs clipboard content between devices via [SyncClipboard Server](https://github.com/Jeric-X/SyncClipboard), WebDAV, or S3-compatible storage.

> No root required: the module injects into `com.android.systemui` for system-level clipboard access. Just activate it in LSPosed.

## Features

- **Auto sync** — local clipboard changes are uploaded automatically; remote changes are pulled via polling / SignalR push
- **Share to upload** — share files/text from any app to this app and upload them to the server (per-file progress)
- **Clipboard history** — browse/search/pin/star, server-side paging, local file disk LRU (200MB / 400 files)
- **Verification codes** — auto-extract and upload SMS / notification codes (optional)
- **Quick settings tile** — one-tap toggle for auto sync, long-press to open the app
- **Multiple backends** — SyncClipboard server (SignalR push), WebDAV, S3-compatible
- **Battery friendly** — backoff retries (30s→5min), disconnect on screen-off / battery saver / mobile data, auto stop after failures
- **MIUIX theme** — bottom bar navigation, liquid glass, Monet dynamic colors (seed color / style / spec)
- **Hot reload** — LSPosed API 102: update the module without restarting SystemUI

## Requirements

- Android 10+ (API 29+)
- LSPosed (hot reload requires LSPosed 2.0+, which supports API 102)
- A compatible clipboard sync server ([SyncClipboard](https://github.com/Jeric-X/SyncClipboard) / WebDAV / S3)

## Module Scope

Enable this module for **`com.android.systemui`**.

## Architecture

The sync engine (`SyncEngine`) runs inside the `com.android.systemui` process and listens to global clipboard changes via the system `ClipboardManager`; the companion app talks to it through `SyncClipboardBridge` (broadcast IPC). Share uploads and preview downloads are performed directly by the app process, while the engine maintains the history database and remote content.

## Build

**Requirements:** JDK 17+; Android SDK (API 37, configured via `ANDROID_HOME` or `sdk.dir` in `local.properties`); the debug keystore is auto-generated by the build.

```bash
./gradlew shell:assembleRelease   # Linux / macOS
gradlew.bat shell:assembleRelease # Windows
```

> Release builds are signed with the standard Android debug key (for sideloading); use a custom keystore by editing `shell/build.gradle.kts`.
